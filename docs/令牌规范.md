# 令牌规范

`<品牌>/tokens.json` 的写法。结构可以用 [`schemas/tokens.schema.json`](../schemas/tokens.schema.json) 在编辑器里检查，完整校验以 `brand-kit check` 为准。

## 1. 格式版本

遵循 W3C Design Tokens 社区组的 **Design Tokens Format Module 2025.10**（DTCG 2025.10）。DTCG 是 W3C 社区组发布的格式，不是 W3C 正式标准。brand-kit 只支持其中一部分类型，另外加了自己的扩展字段（第 3 节）。

## 2. 结构和类型

- 分组是普通对象，令牌是带 `$value` 的对象。`$type` 可以写在分组上，由下级继承。
- 名字只用小写字母、数字和连字符，分组用 `.` 连接成全名，如 `color.brand.primary`。
- 每个令牌必须有 `$description`：写用在哪里、注意什么（比如对比度）。

| `$type` | `$value` 写法 | 例子 |
|---|---|---|
| `color` | 对象：`colorSpace`（只支持 `"srgb"`）、`components`（3 个 0–1 的数）、`hex`（`#rrggbb`），`alpha` 可选 | `{"colorSpace":"srgb","components":[0.1216,0.3059,0.3725],"hex":"#1f4e5f"}` |
| `dimension` | 对象：`value`（数字）、`unit`（`"px"` 或 `"rem"`） | `{"value":12,"unit":"px"}` |
| `fontFamily` | 字符串，或字符串数组（按优先顺序） | `["Source Sans 3","sans-serif"]` |
| `fontWeight` | 1–1000 的数字 | `600` |
| `number` | 数字 | `1.5` |
| `gradient` | 数组，每项 `{color, position}`，position 从小到大、在 0–1 之间；方向写在扩展的 `angle` 里 | `[{"color":"{color.brand.cream}","position":0},{"color":"{color.brand.accent-light}","position":1}]` |

颜色对象不用手算：`npx brand-kit color #1f4e5f` 会直接输出。`components` 和 `hex` 对不上时 check 会报错。

## 3. brand-kit 扩展字段

写在 `$extensions["com.github.dayou-inc.brand-kit"]` 里。DTCG 要求厂商扩展用反向域名作键，这个键对应 `github.com/DAYOU-INC/brand-kit`。

| 字段 | 必填 | 说明 |
|---|---|---|
| `status` | 是 | `confirmed` / `current` / `pending`，含义见 [`方法论.md`](方法论.md) 第 3.3 节 |
| `channels` | 是 | 能用在哪些渠道，见第 4 节；空数组表示只记录、不导出 |
| `source` | 是 | 出处：素材路径和取色方法，或“通用值” |
| `confirmedBy` | status 为 confirmed 时必填 | 确认人和渠道 |
| `confirmedAt` | status 为 confirmed 时必填 | 确认日期 `YYYY-MM-DD` |
| `pendingReason` | status 为 pending 时必填 | 卡在什么问题上 |
| `angle` | 渐变必填 | 角度：90 = 从左到右，180 = 从上到下（CSS `linear-gradient` 的约定） |
| `print` | 否 | `{"cmyk": "...", "pantone": "..."}`，打样后填写 |

## 4. 渠道

| 渠道 | 含义 | 进入哪些生成文件 |
|---|---|---|
| `web` | 网站 | `variables.css`、`tokens.resolved.json` |
| `app` | App | `<品牌>_tokens.dart`、`tokens.resolved.json` |
| `marketing` | 广告、社媒、详情页、营销长图 | `tokens.resolved.json` |
| `print` | 包装、说明书、印刷品 | `tokens.resolved.json` |
| `device` | 设备屏幕和屏幕模拟图 | `tokens.resolved.json` |

规则：

- 使用者只能用渠道包含当前场景的令牌。
- 令牌 A 引用令牌 B 时，A 的 `web`、`app` 渠道 B 也必须有，否则生成的 CSS 或 Dart 会引用不存在的变量。check 会检查这一点。
- Flutter 不支持渐变常量，所以 `app` 渠道里的渐变只会出现在 `tokens.resolved.json` 里，App 自己用其中的色标组装渐变。

## 5. 命名

- **按用途分组，不按颜色名**：`color.brand.primary`、`color.brand.accent`，不写 `color.blue`。颜色以后可能换，用途不会变。
- 推荐的分组：

| 分组 | 放什么 |
|---|---|
| `color.brand.*` | 品牌色（主色、强调色、浅底、深色） |
| `color.neutral.*` | 白、黑、灰 |
| `color.digital.*` | 网站和 App 专用的颜色，或者指向品牌色的别名 |
| `color.device.*` | 设备屏幕专用 |
| `color.line-<产品线>.*` | 某条产品线专用的配色 |
| `color.legacy.*` | 已弃用、只为记录的颜色 |
| `font.*`、`radius.*`、`gradient.*` | 字体、圆角、渐变 |

- 别名用整值引用：`"$value": "{color.brand.primary}"`。生成的 CSS 里会写成 `var(...)`，改了源头，别名会跟着变。
- **不改名、不删除**。下游项目在用生成的变量名，比如 `--acme-color-brand-primary`、`AcmeTokens.colorBrandPrimary`。要替换就新建令牌，旧令牌加 `$deprecated` 过渡，见 [`版本与发布.md`](版本与发布.md)。

## 6. 弃用

```json
"orange": {
  "$value": { "colorSpace": "srgb", "components": [1, 0.4784, 0], "hex": "#ff7a00" },
  "$description": "旧版强调色，已被 color.brand.accent 取代。",
  "$deprecated": "改用 color.brand.accent",
  "$extensions": { "com.github.dayou-inc.brand-kit": { "status": "current", "channels": [], "source": "2024 年旧版详情页" } }
}
```

- `$deprecated` 是 DTCG 的标准字段，可以写 `true`，或者写一句说明改用什么。
- 其他令牌不能引用已弃用的令牌。
- 过渡期间仍要导出的，保留原来的 `channels`：Dart 里会加上 `@Deprecated`，`tokens.resolved.json` 里会带 `deprecated` 字段。不再导出的，把 `channels` 改成 `[]`。

## 7. 生成文件

`brand-kit build` 在 `build/<品牌>/` 下生成以下文件，每次生成前会清空这个目录：

| 文件 | 内容 |
|---|---|
| `variables.css` | 渠道含 `web` 的令牌，变量名是 `--<品牌>-<令牌名用连字符连接>`；别名写成 `var()` |
| `<品牌>_tokens.dart` | 渠道含 `app` 的令牌，类名是 `<品牌>Tokens`，每个常量前面有 `///` 文档注释（说明、状态、渠道、出处） |
| `tokens.resolved.json` | 所有 `channels` 不为空的令牌：值（CSS 写法）、hex、渠道、状态、说明、出处，以及确认人或待处理原因 |
