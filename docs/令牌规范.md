# 令牌规范

`<品牌>/tokens.json` 的写法。`brand-kit check` 会用 [`schemas/tokens.schema.json`](../schemas/tokens.schema.json) 检查结构，再检查本文列出的其他规则。标“（自动检查）”的规则，违反了就报错。

## 1. 格式版本

遵循 W3C Design Tokens 社区组的 **Design Tokens Format Module 2025.10**（下文简称 DTCG 2025.10）。DTCG 是 W3C 社区组发布的格式，不是 W3C 正式标准。brand-kit 只支持其中一部分（第 2 节），另外加了自己的扩展字段（第 3 节）。不支持的写法会报错，不会被悄悄忽略：

- `$root` 令牌
- 颜色的 `alpha`、sRGB 以外的色彩空间
- `typography`、`shadow`、`border` 等复合类型
- 引用令牌的某一部分（比如 `{color.brand.primary.hex}`）

## 2. 结构和类型

- 分组是普通对象，令牌是带 `$value` 的对象。`$type` 和 `$deprecated` 可以写在分组上，由下级继承。
- 名字的每一段只能用小写字母、数字和单个连字符，并以字母开头，比如 `accent-light`。各段用 `.` 连成全名，比如 `color.brand.primary`（自动检查）。
- 不同的令牌不能生成相同的 CSS 变量名或 Dart 常量名，比如 `color.brand-primary` 和 `color.brand.primary` 会撞名（自动检查）。
- 每个令牌必须写 `$description`，说明用在哪里、要注意什么（自动检查）。
- 漏写 `$value` 的对象、空分组、拼错的 `$` 字段都会报错（自动检查）。

| `$type` | `$value` 写法 | 例子 |
|---|---|---|
| `color` | 对象，只有三个字段：`colorSpace`（只支持 `"srgb"`）、`components`（3 个 0–1 的数）、`hex`（`#rrggbb`） | `{"colorSpace":"srgb","components":[0.1216,0.3059,0.3725],"hex":"#1f4e5f"}` |
| `dimension` | 对象：`value`（数字）和 `unit`（`"px"` 或 `"rem"`） | `{"value":12,"unit":"px"}` |
| `fontFamily` | 字符串，或者按优先顺序排列的字符串数组。字体名里不能有 `" \ ; { }` | `["Source Sans 3","sans-serif"]` |
| `fontWeight` | 100–900 之间的整百数字（Flutter 只支持这些值） | `600` |
| `number` | 数字 | `1.5` |
| `gradient` | 数组，每项是 `{color, position}`；position 在 0–1 之间，从小到大排；方向写在扩展的 `angle` 里 | `[{"color":"{color.brand.cream}","position":0},{"color":"{color.brand.accent-light}","position":1}]` |

颜色对象不用手算，运行 `npx brand-kit color "#1f4e5f"` 会直接输出。`#` 要加引号，否则命令行会把它当成注释。`components` 和 `hex` 对不上时会报错（自动检查）。

## 3. brand-kit 扩展字段

扩展字段写在 `$extensions["com.github.dayou-inc.brand-kit"]` 里。DTCG 建议厂商扩展用反向域名作键，这个键对应 `github.com/DAYOU-INC/brand-kit`。出现不认识的字段会报错（自动检查）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `status` | 是 | 取 `confirmed`、`current`、`pending` 之一，含义见 [`方法论.md`](方法论.md) 第 3.3 节 |
| `channels` | 是 | 能用在哪些渠道，见第 4 节；空数组表示只记录、不导出 |
| `source` | 是 | 出处：素材路径加取色方法，或写“通用值” |
| `confirmedBy` | status 为 confirmed 时必填，其他状态不能写 | 确认人和渠道，必须是人；写 AI、推断之类会报错 |
| `confirmedAt` | 同上 | 确认日期，`YYYY-MM-DD`，必须是真实存在的日期 |
| `pendingReason` | status 为 pending 时必填，其他状态不能写 | 卡在什么问题上 |
| `angle` | 渐变必填，其他类型不能写 | 角度：90 表示从左到右，180 表示从上到下（沿用 CSS `linear-gradient` 的约定） |
| `print` | 否 | `{"cmyk": "...", "pantone": "..."}`，只写已经定下来的值；还没定的不要写这个字段，写进第 10 节的待处理 |

## 4. 渠道

| 渠道 | 含义 | 进入哪些生成文件 |
|---|---|---|
| `web` | 网站 | `variables.css`、`tokens.resolved.json`、`tokens.dtcg.json` |
| `app` | App | `<品牌>_tokens.dart`、`tokens.resolved.json`、`tokens.dtcg.json` |
| `marketing` | 广告、社媒、详情页、营销长图 | `tokens.resolved.json`、`tokens.dtcg.json` |
| `print` | 包装、说明书、印刷品 | 同上 |
| `device` | 设备屏幕和屏幕模拟图 | 同上 |

规则：

- 使用者只能用渠道包含当前场景的令牌。
- 整值别名（`"$value": "{color.brand.primary}"`）导出到 `web` 时，被引用的令牌也必须导出到 `web`，因为 CSS 里会写成 `var(...)`（自动检查）。其他引用在生成时都会被解析成具体的值，没有这条限制。
- Flutter 没有渐变常量，渐变只会出现在两个 JSON 文件里。

## 5. 命名

- **按用途分组，不按颜色名分组**：写 `color.brand.primary`、`color.brand.accent`，不写 `color.blue`。颜色以后可能换，用途不会变。
- 推荐的分组：

| 分组 | 放什么 |
|---|---|
| `color.brand.*` | 品牌色（主色、强调色、浅底、深色） |
| `color.neutral.*` | 白、黑、灰 |
| `color.digital.*` | 网站和 App 专用的颜色，或者指向品牌色的别名 |
| `color.device.*` | 设备屏幕专用的颜色 |
| `color.product.*` | 硬件外观（供渲染、包装、AI 生图描述参考） |
| `color.line-<产品线>.*` | 某条产品线专用的配色 |
| `color.legacy.*` | 已经弃用、只为留档的颜色 |
| `font.*`、`radius.*`、`gradient.*` | 字体、圆角、渐变 |

- **不改名、不删除**。下游项目在用生成的变量名，比如 `--acme-color-brand-primary`、`AcmeTokens.colorBrandPrimary`。要替换就新建一个令牌，旧令牌加 `$deprecated` 过渡，见 [`版本与发布.md`](版本与发布.md)。

## 6. 弃用

```json
"orange": {
  "$value": { "colorSpace": "srgb", "components": [1, 0.4784, 0], "hex": "#ff7a00" },
  "$description": "旧版强调色，已被 color.brand.accent 取代。",
  "$deprecated": "改用 color.brand.accent",
  "$extensions": { "com.github.dayou-inc.brand-kit": { "status": "current", "channels": [], "source": "2024 年旧版详情页" } }
}
```

- `$deprecated` 是 DTCG 的标准字段，值可以是 `true`，也可以是一句说明，告诉别人改用什么。写在分组上时，整个分组都算弃用。
- 没有弃用的令牌不能引用已弃用的令牌（自动检查）。
- 过渡期间仍要导出的，保留原来的 `channels`。CSS 注释、Dart 的 `@Deprecated` 和 `tokens.resolved.json` 都会标出“已弃用”，`tokens.dtcg.json` 不收已弃用的令牌。不再导出的，把 `channels` 改成 `[]`。

## 7. 生成文件

`brand-kit build` 在 `build/<品牌>/` 下生成下面这些文件。所有品牌都先在内存里生成，全部成功后才替换 `build/`；任何一个品牌有错，磁盘上的文件都不会动。文件头写着生成它的 brand-kit 版本。

| 文件 | 内容 | 给谁用 |
|---|---|---|
| `variables.css` | 渠道含 `web` 的令牌。变量名是 `--<品牌>-<令牌全名，点换成连字符>`；整值别名写成 `var()`；每个变量上方有说明注释 | 网站 |
| `<品牌>_tokens.dart` | 渠道含 `app` 的令牌，类名是 `<品牌>Tokens`。每个常量前有 `///` 文档注释（说明、状态、渠道、出处）；字重输出为 `FontWeight.wXXX`；字体只保留第一个非系统字体 | Flutter App |
| `tokens.resolved.json` | 所有 `channels` 不为空的令牌，每个令牌包括：CSS 写法的值、hex、渠道、状态、说明、出处，以及确认人或待处理原因、弃用说明 | AI、脚本、其他平台 |
| `tokens.dtcg.json` | 所有导出、没有弃用的令牌，保持 DTCG 结构，引用都已解析成值，并保留扩展字段 | 设计工具导入（比如 Figma 插件） |
