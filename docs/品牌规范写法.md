# 品牌规范写法

`<品牌>/brand.md`、`checks.json`、`source-index.md` 的写法。标“（自动检查）”的规则由 `brand-kit check` 检查，违反就报错。完整例子见 [`example/acme/brand.md`](../example/acme/brand.md)。

## 1. 品牌目录

```
<品牌>/
├── brand.md          规范正文
├── tokens.json       令牌，见 令牌规范.md
├── checks.json       对比度组合、例外色值、禁用名字
├── source-index.md   看过哪些素材、没看到哪些
├── assets/           logo 等标准素材（logo 优先放 SVG）
└── examples/         正反示例图，每张附说明
```

以上文件都必须有（自动检查）。品牌要登记在仓库根目录的 `brand-kit.json` 里，没登记的品牌目录会报错（自动检查）。

## 2. brand.md 的章节

二级标题必须是下面这些，顺序也不能变（自动检查）：

1. `## 1. 品牌和产品`，其中 `### 1.1 正式名称` 列出正式名称；禁用的旧名只能出现在这一节
2. `## 2. Logo`
3. `## 3. 颜色`，其中 `### 3.2 文字对比度` 放自动生成的对比度表
4. `## 4. 字体`
5. `## 5. 图形和图标`
6. `## 6. 图片和视频`
7. `## 7. AI 生成图片`
8. `## 8. 文案`
9. `## 9. 各场景怎么用`：任务表，告诉使用者 AI 每类任务读哪几节、用哪个文件
10. `## 10. 待处理和按现状执行的事项`
11. `## 素材来源`
12. `## 变更记录`

章节固定，是为了让 AI 在上下文有限时，能直接按章节号找到内容。某一节没有素材依据时，写“现有物料没有涉及”，不要删掉这一节。

## 3. 正文规则

| 规则 | 正确 | 错误 |
|---|---|---|
| 提到令牌时写全名，放在反引号里（自动检查：令牌名要存在；不能用简写） | `` `color.brand.primary` `` | `` `brand.primary` ``、`` `primary` `` |
| 可以用 `*` 指一组令牌（自动检查：至少匹配一个） | `` `color.device.*` `` | |
| 写色值时，同一行写出对应的令牌全名（自动检查） | `` 深青 #1F4E5F（`color.brand.primary`） `` | `深青 #1F4E5F` |
| 不是令牌的色值，要登记在 `checks.json` 的 `extraColors` 里并写原因（自动检查） | 实测范围的端点、近似值 | |
| 色值写成 6 位（自动检查） | `#FFFFFF` | `#fff` |
| 状态只用三种说法（自动检查：“待确认、待办、待定、待决定、待统一、未定”和表格里的“确定”都会报错） | 「已确认」「按现状执行」「待处理」 | 待确认、待定 |
| 不能留没填的占位符（自动检查） | | `<产品名>` |
| 禁用的旧名只出现在第 1.1 节（自动检查） | | |
| 素材路径放在反引号里，相对于品牌目录（自动检查：文件要存在） | `` `assets/logo/acme-mark-primary.svg` `` | |
| 链接和锚点要能打开（自动检查） | `[配色](brand.md#31-配色)` | |

不能自动检查、靠写的人自觉的规则：

- 写“是什么”，不写“应该是什么”。建议单独写，并注明是建议。
- 不要编造：没有出处的数值、没见过的产品细节都不要写。
- 写明“只能用在哪里”的限制，并在令牌的 `channels` 里体现。

## 4. 对比度表

第 3.2 节放一对标记，表格由 `brand-kit build` 根据 `checks.json` 的 `contrast` 生成：

```markdown
<!-- brand-kit:contrast 由 brand-kit build 生成，不要手改 -->
<!-- /brand-kit:contrast -->
```

`contrast` 每一项写 `fg`（文字或图形的颜色令牌）、`bg`（底色令牌）、`usage`，`note` 可选：

| usage | 要求（WCAG 2.x） | 用于 |
|---|---|---|
| `text` | ≥ 4.5 | 正文，任意字号 |
| `large-text` | ≥ 3 | 大字：≥ 24px 常规，或 ≥ 18.66px（14pt）粗体 |
| `graphic` | ≥ 3 | 图标、图形、界面元素 |
| `forbidden-text` | 不设下限 | 登记禁止用于文字的组合；如果对比度已经 ≥ 4.5，会报错提示删掉 |

不达标、组合重复、令牌不存在、表格和 `checks.json` 不一致，都会报错（自动检查）。品牌可以比 WCAG 更严，比如规定大字也必须粗体，写在 `note` 和正文里。

## 5. 变更记录

```markdown
| 日期 | 变更 | 确认 |
|---|---|---|
| 2026-11-01 | 主色确认 | 品牌负责人张三，设计评审会，2026-11-01 |
| 2026-11-19 | 初稿 | 未确认 |
```

- 表头必须是 `| 日期 | 变更 | 确认 |`，至少一行（自动检查）。
- 日期格式是 `YYYY-MM-DD`（自动检查）。
- “确认”一列只能写“未确认”，或者“确认人，渠道，YYYY-MM-DD”（自动检查）。

## 6. source-index.md

- **看过的素材**：位置、文件数、内容、用在本标准的哪里。
- **没看到的素材**：位置、原因（没有权限、目录为空……）、可能有什么。
- **怎么访问**：访问方式。不要写密码和 token。

令牌的 `source` 字段写具体出处，`source-index.md` 写总览，两边要对得上。

## 7. checks.json

```json
{
  "contrast": [{ "fg": "color.neutral.white", "bg": "color.brand.primary", "usage": "text" }],
  "extraColors": { "#D2D0D0": "渲染图背景灰的实测上限，只作描述" },
  "names": { "forbidden": [{ "term": "Acme Mill", "use": "Acme Grind G1" }] }
}
```

结构见 [`schemas/checks.schema.json`](../schemas/checks.schema.json)。出现不认识的字段会报错（自动检查）。
