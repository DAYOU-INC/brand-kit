# 品牌规范写法

本文规定 `<品牌>/brand.md`、`checks.json`、`source-index.md` 怎么写。标“（自动检查）”的规则由 `brand-kit check` 检查，违反就报错。完整的例子见 [`example/acme/brand.md`](../example/acme/brand.md)。

## 1. 品牌目录

```
<品牌>/
├── brand.md          规范正文
├── tokens.json       令牌，见 令牌规范.md
├── checks.json       对比度组合、例外色值、禁用名字
├── source-index.md   看过哪些素材、没看到哪些
├── assets/           logo 等标准素材（logo 优先放 SVG）
└── examples/         正反示例图，每张附说明（还没有时放一个 .gitkeep）
```

- 上面四个文件、两个目录都必须有（自动检查）。
- 品牌要登记在仓库根目录的 `brand-kit.json` 里，不能重复登记（自动检查）。
- 有 `tokens.json` 却没登记的目录会报错（自动检查）。

## 2. brand.md 的章节

二级标题必须是下面这些，顺序也不能变（自动检查）：

1. `## 1. 品牌和产品`：其中 `### 1.1 正式名称` 这一节必须有，列出正式名称；禁用的旧名只能出现在这一节（自动检查）
2. `## 2. Logo`
3. `## 3. 颜色`：其中 `### 3.2 文字对比度` 这一节必须有，自动生成的对比度表必须放在这一节里（自动检查）
4. `## 4. 字体`
5. `## 5. 图形和图标`
6. `## 6. 图片和视频`
7. `## 7. AI 生成图片`
8. `## 8. 文案`
9. `## 9. 各场景怎么用`：任务表，告诉使用者 AI 每类任务读哪几节、用哪个文件
10. `## 10. 待处理和按现状执行的事项`
11. `## 素材来源`
12. `## 变更记录`

章节固定，是为了让 AI 在上下文有限时，能直接按章节号找到内容。某一节没有素材依据时，写“现有物料没有涉及”，不要删掉这一节。

## 3. 正文规则

| 规则 | 正确 | 错误 |
|---|---|---|
| 提到令牌时写全名，全小写，放在反引号里（自动检查：令牌名要存在；带点的简写、或者正好等于某个令牌最后一段的单词会报错；渠道名、状态值不算简写） | `` `color.brand.primary` `` | `` `brand.primary` ``、`` `primary` ``、`` `color.Brand.primary` `` |
| 可以用 `*` 指一组令牌（自动检查：至少要匹配到一个） | `` `color.device.*` `` | |
| 正文里写 6 位色值时，同一行要写出对应的令牌全名（自动检查） | `` 深青 #1F4E5F（`color.brand.primary`） `` | `深青 #1F4E5F` |
| 代码块里（比如 AI 提示词）的色值只要求是令牌的值，不要求同一行写令牌名（自动检查） | | |
| 不是令牌的色值，要登记在 `checks.json` 的 `extraColors` 里，并写原因；登记了却没用到的也会报错（自动检查） | 实测范围的端点、近似值 | |
| 色值写成 6 位。只有 6 位的才会被检查；紧跟在字母数字或 `&` 后面的不算色值（不自动检查 3 位和 8 位写法，以免把 `#cafe` 这类话题标签当成颜色） | `#FFFFFF` | `#fff` |
| 状态只用三种说法（自动检查：正文里出现“待确认、待办、待定、待决定、待统一、待核实、待补充、待商定、暂定”，整词出现 TBD、TODO，或者表格里写“确定”，都会报错） | 「已确认」「按现状执行」「待处理」 | 待确认、暂定 |
| 不能留没填的占位符：尖括号里有中文、省略号或 YYYY 的都算，常见 HTML 标签（如 `<img alt="…">`）和自动链接除外。正文、代码块、`source-index.md`、令牌的说明、出处、确认人、印刷色值都会查（自动检查） | | `<产品名>`、`<YYYY-MM-DD>` |
| 禁用的旧名只能出现在第 1.1 节。正文、代码块和令牌说明里都会查，不区分大小写；英文和数字按整词匹配，比如禁用 “Pro 1” 不会误报 “Pro 128”（自动检查） | | |
| 素材路径放在反引号里，相对于品牌目录，大小写要和文件名一致（自动检查：文件要存在） | `` `assets/logo/acme-mark-primary.svg` `` | |
| 链接和锚点要能打开，大小写一致，不能指到品牌库外面。行内链接、带标题的链接、引用式链接都会查（自动检查） | `` `[配色](brand.md#31-配色)` `` | |
| 其他仓库的路径写上仓库名，不要以 `assets/` 开头 | `` `my-website/assets/css/main.css` `` | `` `assets/css/main.css` ``（会被当成本品牌的素材） |

数值的写法：颜色和已经做成令牌的数值（字体、圆角等），正文只写令牌名，不再抄一遍值。没做成令牌的数值（比如 logo 最小尺寸 96px、印刷 20mm）可以直接写在正文里。

不能自动检查、要靠写的人自觉的规则：

- 写“是什么”，不写“应该是什么”。建议要单独写，注明是建议，以及谁提的。
- 不要编造：没有出处的数值、没见过的产品细节都不要写。
- 写清楚“只能用在哪里”的限制，并在令牌的 `channels` 里体现出来。

## 4. 对比度表

第 3.2 节放一对标记。表格由 `brand-kit build` 根据 `checks.json` 的 `contrast` 生成：

```markdown
<!-- brand-kit:contrast 由 brand-kit build 生成，不要手改 -->
<!-- /brand-kit:contrast -->
```

`contrast` 里的每一项写 `fg`（文字或图形的颜色令牌）、`bg`（底色令牌）、`usage`，`note` 可选。阈值按 WCAG 2.x 的 AA 级：

| usage | 要求 | 用于 |
|---|---|---|
| `text` | ≥ 4.5 | 正文，任意字号 |
| `large-text` | ≥ 3 | 大字：≥ 24px（18pt）常规字重，或 ≥ 18.67px（14pt）粗体 |
| `graphic` | ≥ 3 | 图标、图形、界面元素 |
| `forbidden-text` | 不设下限 | 登记禁止用于文字的组合；如果对比度已经 ≥ 4.5，会报错提示删掉这一条 |

表里没有的组合，可以用 `npx brand-kit contrast "#前景" "#底色"` 算。以下情况都会报错（自动检查）：

- 对比度不达标
- 同一组合重复登记
- 令牌不存在，或者不是颜色
- 表格和 `checks.json` 不一致

WCAG 对 logo 和品牌名不做对比度要求，所以 logo 放在什么底色上，写在第 2 节，不用写进这张表。品牌可以比 WCAG 更严，比如要求大字也必须粗体，写在 `note` 和正文里。

## 5. 变更记录

```markdown
| 日期 | 变更 | 确认 |
|---|---|---|
| 2026-11-01 | 主色确认 | 品牌负责人张三，设计评审会，2026-11-01 |
| 2026-11-19 | 初稿 | 未确认 |
```

- 表头必须是 `| 日期 | 变更 | 确认 |`，下面有分隔行，至少一行内容（自动检查）。
- 日期必须是真实存在、不晚于今天的 `YYYY-MM-DD`（自动检查）。
- “确认”一列只能写“未确认”，或者写“确认人，渠道，YYYY-MM-DD”；确认人必须是人，写 AI、推断之类会报错（自动检查）。

## 6. source-index.md

- **看过的素材**：位置、文件数、内容、用在本标准哪里。
- **没看到的素材**：位置、原因（比如没有权限、目录为空）、可能有什么。
- **怎么访问**：访问方式。不要写密码和 token。

令牌的 `source` 写具体出处，`source-index.md` 写总览，两边要对得上。人名只写角色，或者写本人同意公开的名字。

素材来自多处时：

- `source-index.md` 按来源分节（比如“网盘素材”“设计源文件”），每节开头写清这是哪里、谁提供的、怎么访问；导入的现状页面单列一节“看过但不作为依据”，写原因。
- `source` 先写来源，再写位置，最后写方法，能让人原样找到：
  - 网盘文件：`网盘 品牌物料/logo/logo-blue.png 底色取众数`
  - 设计源文件：`设计源文件「Acme 官网」/ 首页 / 色板画框，颜色样式 Brand/Primary`（文件名、页面名、画框或样式名；名字重复时加节点 ID）
  - 几处来源一致：先写定义值的来源，再写“；<另一处> 实测同值”或“实测 #xxxxxx”
- 文件 ID、节点 ID 可以写；访问令牌、分享密码不写。

## 7. checks.json

```json
{
  "contrast": [{ "fg": "color.neutral.white", "bg": "color.brand.primary", "usage": "text" }],
  "extraColors": { "#D2D0D0": "渲染图背景灰的实测上限，只作描述" },
  "names": { "forbidden": [{ "term": "Acme Mill", "use": "Acme Grind G1" }] }
}
```

结构按 [`schemas/checks.schema.json`](../schemas/checks.schema.json) 检查，任何一层出现不认识的字段都会报错（自动检查）。
